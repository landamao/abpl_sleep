# 给AI睡觉

让 AI 按作息睡觉（休息）的插件。

## 工作方式

- AI 通过函数工具自行睡觉：可**立即入睡**，也可创建按 **cron 表达式**定时自动入睡的任务（例如每晚 23:00 准时睡觉）。工具仅对**当前会话**生效，各会话（不同群 / 不同好友）互不影响。
- 睡觉期间，该会话中唤起到 LLM 的消息会被**静默暂存**（不回复），指令（如 `/起床`）不受影响，仍可正常使用。
  暂存内容取自框架处理后的 LLM 请求（prompt + 附加内容），图片转述、引用消息、语音/文件附件标注等跟随框架的处理结果；框架与防抖插入的 `<system_reminder>` 会在合并时清掉。
- 到点自动醒来：把暂存的消息按时间顺序合并（格式 `[Message N; 2026-9-5 15:38:57] 消息`，群聊为 `[Message N; 2026-9-5 15:38:57] 昵称: 消息`，私聊不带昵称），末尾附加配置的醒来提示，重新走完整消息管线请求 LLM（人格、工具、历史记录均正常），由 AI 统一回复。
- **睡前提醒**：定时任务入睡时刻前 N 分钟（默认 5，0 关闭），自动向会话发一次配置的提示词（自动包裹 `<system_reminder>`，`{n}` 为距入睡的分钟数），LLM 可主动说要去睡觉或陪用户聊几句；提醒时刻本身也带随机偏移（±睡前提醒随机误差秒），保证落在入睡之前，每周期只提醒一次。
- 睡觉状态、暂存消息与定时任务全部落盘持久化：重启 / 插件重载后自动恢复定时；醒来时刻已过则启动时立即补唤醒，离线期间错过的任务触发点则启动后立即补触发（已过入睡点就不再补提醒）。

## 工具（工具名与参数名均为英文）

| 工具 | 参数 | 说明 |
| --- | --- | --- |
| `sleep_now` | `duration` / `end_time` 二选一，`silent` 可选 | 立即入睡。到点自动醒来 |
| `create_sleep_task` | `cron`，`duration`，`count` / `jitter` / `name` 可选 | 创建定时睡觉任务：cron 到点自动入睡（睡 `duration`），触发时若已在睡觉则把醒来时间顺延。`count` 不填或 0 表示一直重复，任务执行完自动结束；`jitter` 控制随机时间误差（默认 ±20 分钟）；`name` 是任务名/备注 |
| `cancel_sleep_task` | `task_id` 可选 | 取消定时睡觉任务，不填则取消本会话全部任务；不影响已经进行中的休息 |
| `query_sleep_tasks` | 无 | 查询本会话的睡觉状态与任务列表（任务 ID、cron、剩余次数、下次触发时间） |

- 注意：睡觉中 AI 收不到任何消息、无法调用工具，只能等自然醒来，或由管理员 `/起床` 叫醒。
- 定时任务触发时立即入睡；任务到期次数后自动结束。原 `sleep_tool` / `wake_tool` 已被以上 4 个工具取代。

## 时间参数

- `duration`：支持 `8h` / `20min` / `30`（不带单位为分钟），也可多段组合如 `8h23min`、`1小时30分钟`、`1h30`（不带单位的段按分钟算）。
- `end_time`：支持 `yyyy-mm-dd HH:MM` 或 `HH:MM`（早于当前时刻且超过 2 分钟容差自动算第二天）。
- `cron`：标准 5 位表达式（分 时 日 月 周），如 `0 23 * * *`（每天 23:00）、`30 13 * * 1-5`（工作日 13:30）；指定日期如 `0 23 6 9 *` 可用来安排一次性睡觉。
- `jitter`：随机时间误差，任务每次触发的**入睡时刻**与**醒来时刻**各自在 ±该值 内随机偏移（两者相互独立、每次触发各掷一次），模拟真实作息、避免机械准点。默认 `20min`，单位默认分钟，支持 `min` / `h`，填 `0` 表示完全准点。查询里展示的「下次触发时间」已含当次的入睡随机偏移。

## 指令

| 指令 | 权限 | 说明 |
| --- | --- | --- |
| `/睡觉状态`（别名 `睡了吗`） `[会话ID]` | 所有人 | 查看各会话睡觉安排、定时任务与暂存消息数；带会话 ID（完整或唯一子串）时只看该会话 |
| `/起床` `[会话ID/全部]` | 管理员 | **立刻起床**：结束睡觉安排并把暂存消息立刻交给 LLM 回复（定时任务保留）。不带参数=当前会话 |
| `/取消睡觉` `[会话ID/任务ID]` | 管理员 | **直接取消**：取消睡觉安排和/或定时任务，暂存消息不发给 LLM（要保留请用 `/起床`）。不带参数=当前会话；参数为任务 ID 时精确取消该任务 |

## 配置

- **最长休息小时**：单次休息时长上限（从生效时刻起算），LLM 请求超过该时长时本次睡觉请求被拒绝。
- **最短休息秒**：单次休息时长下限，请求不足时自动补到该值，防止秒睡秒醒（默认 5 秒）。
- **暂存消息上限**：睡觉期间单个会话最多暂存的消息条数，超出丢弃最旧的（默认 100 条）。
- **时间点容差秒**：LLM 填的 `HH:MM` 刚过去多少秒内视为「就是现在」而不是滚到第二天（默认 120 秒）。
- **睡前提醒分钟**：睡前提前多少分钟提醒一次 LLM（默认 5）；0 表示关闭。
- **睡前提醒随机误差秒**：提醒时刻的随机偏移幅度（默认 120 秒），避免每天准点提醒；0 表示准点。
- **睡前提醒内容**：睡前提醒投递给 LLM 的提示词，插件自动包裹 `<system_reminder>`，`{n}` 为距入睡的分钟数；留空表示关闭。
- **醒来提示**：醒来汇总时附加给 LLM 的提示语，支持 `{数量}` 占位符。

## 注意

- 暂存的是框架处理后的请求文本（含附件标注/图片转述/引用内容），不截断。
- 群聊中未 @ 机器人 / 未带唤醒前缀的消息不会触发 LLM，也就不会暂存。
