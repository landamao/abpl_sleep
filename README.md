# 给AI睡觉

让 AI 按作息睡觉（休息）的插件。

## 工作方式

- AI 通过 `sleep_tool` 函数工具自行决定睡觉（例如凌晨 2 点），工具仅对**当前会话**生效，各会话（不同群 / 不同好友）互不影响。
- **开始时间在未来的休息安排是「预约」**：到开始时间才生效，生效前消息照常回复；生效后才拦截暂存。
- 睡觉期间，该会话中唤起到 LLM 的消息会被**静默暂存**（不回复），指令（如 `/起床`）不受影响，仍可正常使用。
  暂存内容取自框架处理后的 LLM 请求（prompt + 附加内容），图片转述、引用消息、语音/文件附件标注等跟随框架的处理结果；框架与防抖插入的 `<system_reminder>` 会在合并时清掉。
- 到点自动醒来：把暂存的消息按时间顺序合并（格式 `[Message N; 2026-9-5 15:38:57] 消息`，群聊为 `[Message N; 2026-9-5 15:38:57] 昵称: 消息`，私聊不带昵称），末尾附加配置的醒来提示，重新走完整消息管线请求 LLM（人格、工具、历史记录均正常），由 AI 统一回复。
- 睡觉状态与暂存消息落盘持久化：重启 / 插件重载后自动恢复定时；若醒来时刻已过，启动时立即补唤醒。

## 工具

- `sleep_tool`：睡觉/休息。`开始时间` 省略即立即开始（LLM 填了当前时间也有 2 分钟容差兜底，不会误滚到第二天）。`静默执行` 设为 true 时立即入睡、忽略开始时间，工具不返回内容并直接结束本轮对话（适合深夜按作息该睡却收到消息的场景）；休息时长超过配置上限时本次请求会被拒绝。
- `wake_tool`：取消**还没开始**的休息安排（改主意不睡了）。注意睡觉中 AI 收不到任何消息，因此无法在睡觉中用工具取消，只能等自然醒来或管理员 `/起床`。

## 时间参数

`开始时间` / `结束时间` 支持 `yyyy-mm-dd HH:MM` 或 `HH:MM`（早于当前时刻且超过 2 分钟容差自动算第二天）；
`持续时间` 支持 `8h` / `20min` / `30`（不带单位为分钟），也可多段组合如 `8h23min`、`1小时30分钟`、`1h30`（不带单位的段按分钟算）。填了 `持续时间` 时 `结束时间` 无效。

## 指令

| 指令 | 权限 | 说明 |
| --- | --- | --- |
| `/睡觉状态`（别名 `睡了吗`） | 所有人 | 查看各会话睡觉安排（区分睡觉中 / 待生效）与暂存消息数 |
| `/起床` | 管理员 | 叫醒当前会话；安排还没生效则直接取消 |
| `/起床 全部` | 管理员 | 处理所有会话的睡觉安排 |

## 配置

- **最长休息小时**：单次休息时长上限（从生效时刻起算），LLM 请求超过该时长时本次睡觉请求被拒绝。
- **醒来提示**：醒来汇总时附加给 LLM 的提示语，支持 `{数量}` 占位符。

## 注意

- 暂存的是框架处理后的请求文本（含附件标注/图片转述/引用内容），不截断。
- 每个会话最多暂存 100 条，超出丢弃最旧的。
- 群聊中未 @ 机器人 / 未带唤醒前缀的消息不会触发 LLM，也就不会暂存。
